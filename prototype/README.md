# 프로토타입 웹 (`@gb/prototype`)

MCP 에이전트에 붙는 Next.js 화면입니다. 질문을 받으면 에이전트가 데이터에서 근거를
모으고, 그 근거를 **카드 형태**로 그립니다. 줄글 답변을 렌더링하지 않습니다.

## 실행

```bash
# 1) 데이터 백엔드(MCP HTTP 서버)
pnpm dev                    # http://127.0.0.1:8787

# 2) 프로토타입
pnpm prototype:dev          # http://localhost:3100
```

`CLAUDE_API_KEY`는 저장소 루트 `.env`에서 자동으로 읽습니다. 다른 백엔드 주소나
모델을 쓰려면 `prototype/.env.local`에 적습니다(`.env.local.example` 참고).

| 변수 | 기본값 | 설명 |
| --- | --- | --- |
| `MCP_BASE_URL` | `http://127.0.0.1:8787` | 에이전트 API 주소 |
| `MCP_AUTH_TOKEN` | (없음) | 서버가 토큰 인증 모드일 때만 필요 |
| `PROTOTYPE_MODEL` | `claude-sonnet-5` | 근거를 카드로 배치하는 모델 |

모델은 역할이 둘로 나뉜다. **도구 선택**은 MCP 서버의 `PLANNER_MODEL`(현재
`gpt-5.6-sol`)이, **화면 구성**은 이 앱의 `PROTOTYPE_MODEL`(현재 `claude-sonnet-5`)이
맡는다. 어떤 조합이 쓰였는지는 답변 아래에 그대로 표시된다.

## 화면

| 경로 | 내용 |
| --- | --- |
| `/` | 지역·나이·관심분야를 받는 첫 화면. 세션 저장소에만 남습니다. |
| `/ask` | 자유 질문 입력과 대표 질문 칩. |
| `/chat` | 사이드바 + 대화. `?q=질문`으로 바로 물어볼 수 있습니다. |
| `/guide` | 이 화면이 무엇을 보장하고 무엇을 하지 않는지. |

## 구조

```
질문 → /api/chat → MCP /api/agent  (gpt-5.6-sol이 도구를 고르고 서버가 호출·수집)
                 → claude-sonnet-5 (모인 근거를 블록 JSON으로 배치)
                 → zod 검증 → 카드 렌더링
```

- 모델 응답이 스키마를 벗어나면 그 블록만 버리고, 남는 게 없으면 근거로 직접 그리는
  결정적 렌더러(`lib/fallback.ts`)로 대체합니다.
- 백엔드가 응답하지 않으면 답을 지어내지 않고 연결 실패를 화면에 표시합니다.
- 「에이전트 경로」 패널에 카탈로그 후보, 실제 호출한 도구와 인자, 거부된 호출,
  비어 있던 데이터셋이 그대로 노출됩니다.

## 스트리밍

답 하나에 30~45초가 걸립니다. `/api/chat`은 서버-전송 이벤트로 진행을 흘려보내고,
화면은 그것을 「추론 과정」으로 그립니다.

```
stage(도구 선택) → tool×N → stage(근거 수집) → stage(화면 구성) → summary → block×N → done
```

여기에 표시되는 단계와 도구 이름은 전부 서버가 보낸 실제 값입니다. 기다리는 시간을
채우려고 진행 문장을 지어내지 않습니다. 중간에 보이는 카드는 미리보기이며, 마지막에
응답 전체를 다시 검증한 결과로 교체됩니다.

자세한 내용은 `docs/CHANGES_PROTOTYPE_STREAMING_UI.md`를 참고하세요.
