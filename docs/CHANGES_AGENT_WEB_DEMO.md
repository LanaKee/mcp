# 변경: 웹 프로토타입을 에이전트 경로로 전환

## 배경

`/api/demo`는 `questionId`를 받아 미리 작성된 도구 호출 시퀀스를 실행했다. 네 개의
대표 질문마다 어떤 도구를 어떤 인자로 부를지, 결론 문장을 어떻게 조립할지가 전부
코드에 박혀 있었다.

이 구조의 문제는 **데모가 아무것도 증명하지 못한다**는 것이다. 사람이 미리 정답
경로를 써 둔 질문 네 개만 동작하고, 사용자가 다른 질문을 입력하면 답할 수 없다.
"AI가 데이터를 발견하고 연결한다"가 이 프로젝트의 주장인데, 화면에 보이는 것은
사람이 짜 둔 분기의 실행 결과였다.

## 무엇을 바꿨나

### 1. `/api/demo`와 `runRepresentativeDemo`를 제거했다

`services/mcp-server/src/demo.ts`(280줄)를 삭제하고
`services/mcp-server/src/questions.ts`로 대체했다. 새 파일에는 **질문 문자열만**
남았다. 도구도, 데이터셋도, 연도 구간도, 결론 틀도 없다.

```ts
export const representativeQuestions = [
  { id: "population-tax", question: "포항시는 2018년부터 2024년까지 인구는 줄었는데 지방세 세수는 늘었나?" },
  ...
] as const;
```

`/api/questions`는 그대로 두었다. 시작점을 제시하는 것과 정답 경로를 심어 두는 것은
다르다.

### 2. 웹 앱이 `/api/agent`만 호출한다

`apps/web`에 자유 질문 입력창을 추가했다. 대표 질문 버튼도 입력창을 채운 뒤 같은
`/api/agent`를 호출한다. **데모는 사용자가 재현할 수 없는 경로를 절대 보여주지
않는다.**

### 3. 에이전트의 경로를 화면에 노출했다

결론보다 **먼저** 「에이전트 경로」 패널을 보여준다.

| 단계 | 내용 |
| --- | --- |
| 카탈로그 검색 | 후보 데이터셋과 각각이 일치한 용어, 적재 여부 |
| 도구 선택 | 실제 호출한 도구와 인자 전체 |
| 거부된 호출 | 플래너가 요청했으나 안전 경계가 막은 호출과 사유 |
| 비어 있는 데이터셋 | 질문에 관련되지만 행이 없는 데이터셋 |
| 근거 수집 | 근거 건수와 출처 건수 |

숨기면 데모의 핵심이 사라진다. 데이터셋 선택과 도구 선택이 요청 시점에 결정되고
그 결정을 감사할 수 있다는 것이 이 시스템의 주장이기 때문이다. 결합이 일어난
경우에는 join key와 comparability caveat을 별도 패널로 보여준다.

## 대표 질문을 실측 기반으로 다시 골랐다

기존 질문 중 「상주에서 스마트팜 창업을 준비 중인 34세에게 맞는 정책은?」은
`policy_program` 테이블에 행이 0건이라 답할 수 없었다. 「정보공개청구서 초안」은
데이터 질의가 아니라 문서 생성이었다.

새 여섯 개는 각각 **다른 동작**을 드러내도록 골랐고, 전부 적재된 데이터에 대해
실행해 확인했다.

| id | 드러내는 것 | 실측 결과 |
| --- | --- | --- |
| `population-tax` | 두 데이터셋을 선언된 join으로 결합 | 도구 2개, join 1개, caveat 2건 |
| `uljin-population` | 지역별 커버리지 부족 시 거절 | 답변 거절, "2025~2026년만 적재" 고지 |
| `press-depopulation` | 같은 주제어에서 문서 검색 | `search_press_releases`, 출처 1건 |
| `council-depopulation` | 같은 주제어에서 의안 검색 | `search_member_bills` |
| `youth-policy` | 빈 데이터셋 고지 | `policy_program` 0행 고지 후 보도자료로 답변 |
| `mars-water` | 범위 밖 질문 거절 | 후보 0개, 계획 0개 |

`press-depopulation`과 `council-depopulation`이 나란히 있는 이유는, 같은 "지방소멸"
이라는 단어에서 서로 다른 도구로 갈라진다는 것을 보이기 위해서다.

## 테스트

`/api/demo` 테스트를 지우고 네 개를 추가했다.

- 대표 질문 목록이 `id`와 `question` **외의 키를 갖지 않는지** 검사한다. 도구나
  답변이 다시 섞여 들어오는 순간 실패한다.
- `/api/agent`가 `planner`, `consideredDatasets`, `plan`, `conclusion`, `sources`를
  모두 반환하는지 검사한다. 화면이 렌더링하는 필드가 계약이다.
- 빈 질문과 500자 초과 질문이 400을 받는지 검사한다.

전체: 296 passed / 47 skipped.
