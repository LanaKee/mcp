# 프로토타입 모바일 하이파이 반영

앞서의 반응형 작업이 "가로로 넘치지 않는다"까지였다면, 이번에는 피그마
하이파이 목업(iPhone 17, 7화면)의 **배치와 색까지** 맞췄다.

## 화면 흐름이 하나 늘었다

목업의 첫 화면은 스플래시다. 이전 작업에서는 "새 라우트는 데스크톱 흐름까지
바꾼다"는 이유로 넘겼는데, 하이파이에 명시적으로 들어 있으므로 구현했다.

- `/` → 스플래시 (배지, Welcome to G:TEXTFLOW, 시작하기)
- `/intake` → 기존 상황 입력 (원래 `/`에 있던 화면)
- `/ask` → 질문
- `/chat` → 대화

사이드바의 "내 상황 다시 설정"이 `/intake`를 가리키도록 함께 옮겼다.

첫 화면에서 아무것도 묻지 않는 것이 이 배치의 요점이다. 열자마자 지역·나이·
관심분야를 요구하면, 무엇을 얻게 되는지 모르는 채로 입력부터 하게 된다.

## 목업에서 색을 직접 읽었다

눈으로 맞추는 대신 목업 PNG의 픽셀을 뽑았다.

| 위치 | 목업 | 반영 |
| --- | --- | --- |
| CTA 버튼 · 배지 | `#6ac48a` | 기존 `mint-500`(`#6ac68d`)과 사실상 동일 |
| 사용자 말풍선 · 아바타 | `#60d095` | `mint-400`을 `#7ddba3` → `#63d195`로 |
| 페이지 배경 | `#131415` | `ink-950`을 `#0f1011` → `#131415`로 |

CTA 버튼 글자는 목업에서 **흰색**이다. 초록 위 흰 글자는 대비가 낮지만
(약 2.1:1) 브랜드 결정으로 보고 그대로 따랐다. 같은 초록 위에서도 말풍선
글자는 어두운 색이므로, 두 경우를 구분해 적용했다.

## 대화 화면

- 헤더는 좁은 화면에서 **햄버거 하나만** 남긴다. 새 대화·공유는 서랍 안에
  있으므로 기능이 사라지지 않는다
- 사용자의 말은 초록 말풍선, 시각과 편집·복사는 그 **아래 오른쪽**으로
  옮겼다. 답변 머리글에 있으면 그 시각이 질문 시각인지 답변 시각인지
  읽는 사람이 알 수 없다
- 답변 머리글은 두 줄이 됐다. 이름 아래에 연결된 데이터 이름이 온다
- 대화를 감싸던 패널을 좁은 화면에서 없앴다. 목업에서는 대화가 배경 위에
  바로 놓인다. 넓은 화면에서는 그대로 둔다
- 입력 바를 알약 하나로 바꿨다. `+`, 입력, 마이크, 녹음이 한 줄에 놓이고
  높이는 내용만큼만 늘어난다(최대 128px)
- 오른쪽 초록 버튼은 **입력이 비면 녹음, 있으면 보내기**다. 같은 자리에서
  모양만 바뀌므로 누를 곳을 다시 찾지 않아도 된다. 이전에는 비었을 때
  흐려져서 고장 난 것처럼 보였다

## 안전영역 유틸리티가 원래 여백을 지우고 있었다

`.safe-bottom { padding-bottom: env(safe-area-inset-bottom) }`은 같은 요소에
붙은 `py-10`의 하단 패딩을 **통째로 덮어썼다.** 안전영역이 0인 환경에서는
`padding-bottom: 0`이 되어 스플래시의 시작하기 버튼이 화면 밖으로 잘렸다.
대화 화면의 아래 여백도 같은 이유로 사라져 있었다.

클래스를 없애고 값만 변수로 내보낸 뒤, 쓰는 쪽에서 큰 값을 고르게 했다.

```
:root { --safe-t: env(safe-area-inset-top, 0px); --safe-b: env(safe-area-inset-bottom, 0px); }

pb-[max(2.5rem,var(--safe-b))]
```

안전영역이 없는 기기에서는 디자인 여백이, 노치가 있는 기기에서는 안전영역이
이긴다. 어느 쪽도 상대를 지우지 않는다.

## 검증

CDP 모바일 에뮬레이션(390×844, `mobile: true`, dpr 2).

- 6개 화면 모두 `scrollWidth === 390`, 가로 넘침 0건
- 답변 카드 8종(headline·scenario·metricGrid·briefing·series·table·bullets·
  callout)을 한 화면에 넣어 렌더링 확인. 표까지 390px 안에 들어간다
- 1280px에서 사이드바·패널·2열 브리핑이 그대로인지 확인 (회귀 없음)
- 테스트 472건 통과, 프로덕션 빌드 성공

MCP 터널(`use.me.kr`)이 502로 내려가 있어 실제 질의를 끝까지 돌릴 수 없었다.
바꾼 것이 렌더링이므로, 화면이 실제로 받는 것과 같은 모양의 `ChatReply`를
`localStorage`에 넣어 검사했다. 도구는 세션 작업물의 `mobile-fixture.mjs`다.

터널이 죽어 있는 동안 화면이 보인 반응도 함께 확인했다 — "도구 호출이
중단되었습니다 / 근거 없이 답을 지어내지 않습니다"로 멈췄다. 의도한 동작이다.

## 목업과 남은 차이

- 서랍 하단의 계정 카드(Rami / Free / Pro로 업그레이드하기)는 인증이 없는
  서비스라 "지역 미설정 / 맥락 없이 질문합니다" 맥락 카드로 대신한다
- 추천 질문 칩은 목업이 짧은 라벨(`청년 창업 지원`)인데, 실제 목록은 MCP
  서버가 주는 완성된 문장이라 길다. 한 줄로 잘라 알약 모양을 유지했다
