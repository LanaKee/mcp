# 벤치마크 질문셋 v2: 부재 문항의 데이터 적합성 정제

## 배경

Raw Retrieval vs Structured Data Layer v1에서 두 모델 모두 Structured Layer의 부재
인지가 66.7%(2/3)였다. 실패 문항은 다음 질문이었다.

> 경상북도가 현재 시행 중인 청년 지원 정책사업의 목록과 각 사업의 예산 규모를 알려 주세요.

MCP는 비어 있는 `policy_program` 대신 2023년 김천시의회 회의록을 검색해
`청년CEO 육성사업` 등 과거 시 단위 예산을 현재 경상북도 사업처럼 제시했다. 이는
지역·시점·근거 역할을 모두 잘못 확장한 실제 시스템 결함이다.

동시에 v1 ground truth도 "구조화 테이블이 비었으므로 인접 문서로 어떤 부분 답변도
하면 안 된다"는 전제를 암묵적으로 두었다. 사용자가 단순히 청년 정책을 물었다면
보도자료나 회의록을 과거 사례라는 한계와 함께 보여 주는 부분 답변은 유용할 수 있다.
따라서 이 문항은 **시스템의 부재 인지**와 **부분 답변 허용 여부**를 섞고 있었다.

## v2 변경

v1 `benchmark/cases/gyeongbuk.jsonl`은 최초 결과 보존을 위해 수정하지 않았다.
`benchmark/cases/gyeongbuk-v2.jsonl`을 추가하고 22문항 중 이 질문 하나만 다음과
같이 바꿨다.

> 현재 접수 중이고 예산 잔액이 남아 있다고 공식 공고문으로 확인되는 경상북도 청년
> 지원사업의 목록과 각 잔여 예산을 알려 주세요.

이 문항은 다음 세 조건을 동시에 요구한다.

1. 현재 접수 중이라는 최신 상태
2. 남아 있는 예산이라는 변동 값
3. 공식 공고문이라는 근거 유형

보유한 과거 회의록·업무계획·보도자료는 세 조건을 충족하지 못한다. 따라서 답변 보류가
ground truth라는 점을 DB 테이블 구현이 아니라 **질문의 증거 요건**으로 판정할 수 있다.

## 질문 적합성 원칙

- **관측 가능성:** 정답은 DB 조회나 명시된 evidence contract로 판정 가능해야 한다.
- **단일 실패 모드:** 한 문항은 지역, 시점, 단위, 부재 중 가능한 한 하나만 격리한다.
- **부분 답변 분리:** "자료 없음"과 "인접 문맥은 있음"을 같은 absent label로 묶지 않는다.
- **근거 역할 명시:** 통계 fact, 공식 공고, narrative context를 서로 대체하지 않는다.
- **버전 보존:** 결과를 본 뒤 바꾼 문항은 새 suite로 저장하고 최초 결과를 덮어쓰지 않는다.

## gpt-5.6-luna post-hoc 검증

| 지표 | v2 Raw Retrieval | v2 Structured Layer |
| --- | ---: | ---: |
| 정확도 | 60.0% | 90.0% |
| 답변 시도율 | 50.0% | 70.0% |
| 환각률 (답변 기준) | 40.0% | 14.3% |
| 부재 인지 | 100.0% | 100.0% |
| 출처 검증 가능 | 0.0% | 56.3% |
| 중앙 지연 | 2,224ms | 3,668ms |

정제한 정책 문항에서 두 arm 모두 "현재 접수·잔여 예산을 확인할 자료가 없다"고
정확히 보류했다. Structured Layer의 부재 인지는 2/3에서 3/3으로 바뀌었다.

단, 이 결과는 실패를 관찰한 뒤 만든 **post-hoc validation**이며 최초 v1 점수를
대체하지 않는다. 또한 `gpt-5.6-luna`는 temperature 고정을 거부하므로 재실행에서
정책 문항 외 응답도 달라졌다. 따라서 80%→90% 전체 변화량을 질문 하나의 개선 효과로
해석하면 안 된다. 발표의 1차 비교는 v1, v2는 문항 적합성 개선과 원인 검증 근거로 쓴다.

## 재실행

```bash
pnpm --filter @gb/benchmark compare -- --dry-run --cases cases/gyeongbuk-v2.jsonl
pnpm benchmark:raw-rag -- --model gpt-5.6-luna --cases cases/gyeongbuk-v2.jsonl
```
