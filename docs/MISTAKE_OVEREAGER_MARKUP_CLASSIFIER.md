# 실수: 표본 2건으로 만든 분류기가 유효 레코드 400건을 삭제 처리함

## 무엇이 잘못되었나

경상북도 보도자료를 적재한 뒤 `content_classification = 'mojibake_suspected'`로
표시된 2건을 확인했다. 두 건 모두 인코딩 깨짐이 아니라 HWP에서 내보낸 HTML
문서 전체가 본문에 붙여넣어진 경우였다. 라벨이 사실과 달랐으므로
`unusable_for_retrieval`로 정정하는 것이 맞았고, 이를 위해
`looksLikeMarkupSource()`를 추가했다.

문제는 판정 기준이었다. 확인한 표본 2건에서 관찰된 문자열을 마커 목록으로
만들고 "2개 이상 일치하면 마크업"이라고 정했다. 재적재 결과 예상했던 2건이
아니라 **406건**이 `unusable_for_retrieval`이 되었다.

`unusable_for_retrieval` 행은 `searchPressReleases()`의 `WHERE` 절에서 제외된다.
즉 검색에서 완전히 사라진다. 2020년 데이터는 330건 중 304건이 사라져
**해당 연도 커버리지의 92%가 조용히 소실**되었다. 오류도, 경고도 없었다.

## 왜 놓쳤나

분류기의 **양성 클래스만 검증**했다. "마크업으로 판정된 것이 실제로 마크업인가"는
확인했지만, "마크업이 아니라고 판정되어야 할 것이 살아남았는가"는 확인하지 않았다.
적재 후 개수를 세어보고 나서야 규모를 알았고, 그때조차 처음에는 데이터가 원래
그런 줄 알았다.

근본 원인은 표본 편향이다. 2건은 본문 **전체**가 스타일시트인 극단적인 사례였고,
나머지 400건은 게시판이 앵글 브래킷을 제거한 채 서빙한 HWP 문서로,
스타일 선언 사이사이에 **정상적인 한국어 본문이 그대로 들어있었다**.
두 부류는 같은 마커를 공유하지만 가치가 정반대다.

## 실제 데이터의 형태

게시판은 붙여넣은 HWP HTML의 앵글 브래킷을 제거한 뒤 `<br/>`만 남겨 서빙한다.
태그가 태그로 보이지 않으므로 일반적인 태그 제거기는 아무것도 지우지 못한다.

```
BODY
P CLASS=HStyle0 STYLE=text-align:center;line-height:130%;SPAN STYLE=font-size:16.0pt;font-family:휴먼명조;line-height:130%제           목/SPAN/P
...
/BODY
```

`line-height:130%` 다음에 곧바로 `제 목`이 이어진다. CSS 값과 본문 사이에 구분자가
없다. 그래서 `[^;]*` 같은 느슨한 패턴을 쓰면 본문까지 통째로 먹어버린다.

## 어떻게 고쳤나

버리는 대신 **복구**했다. `recoverHwpMarkupBody()`는

1. `BODY` ~ `/BODY` 구간만 남기고 문서 프리앰블 줄을 제거한다.
2. CSS 선언을 느슨한 `[^;]*`가 아니라 **엄격한 토큰 문법**으로 파싱한다.
   값은 숫자+단위, `#색상`, 식별자만 허용하므로 `130%` 다음의 `제`에서 정확히 멈춘다.
   한글이 들어갈 수 있는 `font-family` / `style-name`만 세미콜론까지 허용한다.
3. `/SPANSPAN`처럼 구분자를 잃고 붙어버린 태그 때문에 한 번의 패스로는 절반만
   지워진다. 변화가 없을 때까지 최대 6회 반복한다.
4. **복구 결과를 다시 검사한다.** 마크업이 남아 있으면 원본을 그대로 돌려준다.

4번이 핵심 안전장치다. 반쯤 정리된 텍스트를 저장하는 것은 정직하게
`unusable_for_retrieval`로 두는 것보다 나쁘다. 어중간한 결과는 검색에 노출되면서도
읽을 수 없기 때문이다.

`looksLikeMarkupSource()`는 이제 복구 이후에만 동작하므로,
"마크업이다"가 아니라 "복구에 실패했다"를 뜻한다.

## 결과

| 연도 | 이전 `extracted_ok` | 이후 `extracted_ok` |
| --- | --- | --- |
| 2020 | 26 / 330 | 329 / 330 |
| 2021 | 699 / 797 | 797 / 797 |
| 2025 | 2,766 / 2,770 | 2,766 / 2,770 |
| 전체 | 13,301 / 13,707 | 13,702 / 13,707 |

남은 5건은 본문이 비어 있는 4건과, 문서 본문 없이 스타일시트만 있어
복구할 것이 없는 1건이다.

## 다음에 지킬 것

- **분류기는 음성 클래스를 먼저 검증한다.** "걸러낸 것"이 아니라 "남긴 것"을 센다.
  적재 전에 전체 코퍼스에 대해 판정 분포를 뽑아보고 예상치와 비교한다.
- **표본 2건으로 규칙을 만들지 않는다.** 최소한 판정에 걸린 전체 집합을
  훑어보고 이질적인 부류가 섞여 있는지 확인한다.
- **데이터를 버리는 판정은 되돌릴 수 있게 만든다.** 여기서는 복구 실패 시
  원본을 유지하도록 해서, 잘못 판정해도 원문이 남는다.
- 회귀 테스트는 양방향으로 작성한다. `load-plan.test.ts`에 "복구 불가능한
  문서는 unusable"과 "복구된 본문은 extracted_ok" 두 개를 모두 둔다.
