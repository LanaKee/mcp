# 안전영역 유틸리티가 디자인 여백을 지웠다

## 증상

스플래시 화면의 "시작하기" 버튼이 화면 아래로 잘려 나갔다. 컨테이너에
분명히 `py-10`(위아래 40px)을 줬는데 아래쪽만 0이었다.

## 원인

```css
.safe-bottom {
  padding-bottom: env(safe-area-inset-bottom);
}
```

```jsx
<main className="safe-bottom flex min-h-dvh flex-col px-6 py-10">
```

`py-10`과 `.safe-bottom`은 둘 다 `padding-bottom`을 건드리고, 특정도가 같다.
스타일시트에서 나중에 나오는 쪽이 이긴다. `.safe-bottom`이 이겼고,
안전영역이 없는 환경에서 `env(safe-area-inset-bottom)`은 `0px`이므로
**하단 패딩이 40px에서 0으로 사라졌다.**

노치를 피하려고 넣은 클래스가, 노치가 없는 기기에서 여백을 없애는 클래스로
동작했다. 시뮬레이터에서만 확인했다면 정상으로 보였을 것이다.

같은 문제가 대화 화면에도 있었다. `p-3`과 `.safe-bottom`이 겹쳐 아래
안쪽 여백이 사라져 있었는데, 입력 바가 그 자리를 채우고 있어서 눈에 띄지
않았다.

## 고친 방법

클래스가 값을 **정하지 않게** 했다. 값만 변수로 내보내고, 쓰는 쪽에서
원래 여백과 큰 쪽을 고른다.

```css
:root {
  --safe-t: env(safe-area-inset-top, 0px);
  --safe-b: env(safe-area-inset-bottom, 0px);
}
```

```jsx
<main className="px-6 pt-[max(2.5rem,var(--safe-t))] pb-[max(2.5rem,var(--safe-b))]">
```

이제 두 값이 경쟁하지 않는다. 안전영역이 0인 기기에서는 디자인 여백이,
노치가 큰 기기에서는 안전영역이 이긴다. 어느 쪽도 상대를 지우지 않는다.

## 남는 교훈

**같은 속성을 쓰는 유틸리티를 한 요소에 겹쳐 붙이면, 둘 중 하나는 조용히
사라진다.** 특정도가 같으면 승부는 소스 순서가 정하는데, 그 순서는 클래스를
쓰는 쪽에서 보이지 않는다.

특히 `env()`처럼 **환경에 따라 0이 되는 값**을 쓰는 유틸리티는 위험하다.
값이 있을 때는 잘 동작하는 것처럼 보이다가, 0인 환경에서 원래 있던 값까지
0으로 만든다. 이런 값은 덮어쓰는 자리가 아니라 `max()` 안에 넣어야 한다.
