# 프롬프트 플래너를 걷어내고 네이티브 MCP 도구 호출로 전환

## 무엇이 잘못돼 있었나

프로토타입은 MCP 서버를 쓰면서도 **MCP 프로토콜로 도구를 부르지 않았다**. 실제 경로는 이랬다.

1. `prototype` → `POST /api/agent` (우리가 만든 REST 엔드포인트)
2. `services/mcp-server`가 카탈로그를 검색해 후보 데이터셋을 추린다
3. 그 후보와 도구 설명을 **프롬프트 글로 적어** 모델에게 넘긴다
4. 모델이 돌려준 JSON을 우리가 파싱해 도구를 **대신** 호출한다

도구를 부를 줄 아는 모델에게 도구를 설명한 글을 읽히고, 그 답을 다시 우리가 번역하고 있었다. 번역 계층마다 고유한 실패가 하나씩 붙어 있었다.

| 계층 | 실패 |
| --- | --- |
| 카탈로그 어휘 게이트 | `press_release`의 keywords가 형식어(보도자료·의안)뿐이라 "스마트팜 창업 지원사업" 같은 주제어는 통과하지 못한다. 324건이 있어도 후보에 오르지 않는다 |
| 프롬프트 플래너 | 한 번에 계획을 통째로 세우고 끝난다. 첫 호출 결과를 보고 다음 호출을 정할 수 없다 |
| 결과 번역 | 도구 결과가 프롬프트를 거쳐 오므로 모델은 원본 스키마를 보지 못한다 |

증상은 명확했다. "34세인데 경북에서 스마트팜 창업을 하려면?" 질문에 `plan=0`, `answered=false`가 나왔다. 데이터는 전부 있었다(스마트팜 324건, 임대형 34건, 혁신밸리 64건, 농어촌진흥기금 30건). 검색을 **시도조차 하지 않은** 것이다.

## 무엇을 바꿨나

모델을 MCP 서버에 직접 붙였다. OpenAI Responses API의 원격 MCP 도구를 쓴다.

```ts
tools: [{ type: "mcp", server_label: "gyeongbuk", server_url: MCP_SERVER_URL(), require_approval: "never" }]
```

도구 목록·스키마·결과가 모두 프로토콜을 통해 오간다. 우리가 옮겨 적을 것이 없고, 모델은 결과를 보고 다음 호출을 정한다.

### 새 파일: `prototype/src/lib/mcp-agent.ts`

`askViaMcp(question, handlers, signal)`가 Responses 스트림을 읽어 기존 `AgentAnswer` 모양으로 옮긴다. **화면 계약은 그대로 두었다.** 구성 단계(`compose.ts`)와 렌더러는 무엇이 바뀌었는지 모른다.

- `mcp_call` 아이템 → `plan` + `evidence`
- 결과 JSON을 재귀로 훑어 `sourceId`/`sourceIds`를 전부 수집 (도구마다 결과 모양이 달라 위치를 가정할 수 없다)
- `search_datasets`를 불렀을 때만 `consideredDatasets`를 채운다
- 실패한 호출은 버리지 않고 `rejectedSteps`에 남긴다 — "그 데이터는 없다"와 "찾아보지 않았다"는 다른 말이다
- 도구를 한 번도 성공시키지 못하면 결론 문장이 있어도 `answered=false`. 근거 없이 남은 글은 모델이 기억에서 쓴 문장이다

### 추론 과정 스트리밍

`reasoning: { summary: "auto" }`로 요청하고 `response.reasoning_summary_text.delta`를 새 `reasoning` 이벤트로 흘려보낸다. 화면은 최근 400자만 흐리게 보여준다. 완결된 주장으로 읽히면 안 되기 때문이다.

### 라우트 패널의 거짓말 수정

후보가 0개일 때 무조건 "이 질문은 보유 범위 밖입니다"라고 말하고 있었다. 네이티브 MCP에서는 모델이 `search_datasets`를 건너뛰고 곧장 도구를 부르는 일이 흔하고, 그때도 도구는 돌고 근거는 쌓인다. **도구 4건이 성공하고 출처가 5건인데 화면은 범위 밖이라고 말했다.** 실행된 호출이 있으면 "카탈로그를 검색하지 않고 도구를 직접 골랐습니다"로 구분한다.

호출마다 붙던 `"모델이 MCP 프로토콜로 직접 호출"` 상수 문자열도 없앴다. 같은 문장을 네 번 반복하는 것은 정보가 아니라 잡음이다.

## 함께 고친 구성 단계 결함

전환 검증 중에 드러난 것들이다. MCP 전환으로 답이 길어지면서 표면화됐다.

### 1. 출력 토큰 상한 (4096 → 12000)

한국어 브리핑 한 화면은 카드 대여섯 장에 표까지 들어가 4096토큰을 넘긴다. 상한에 걸리면 JSON이 배열 한가운데서 끊기고, 화면 전체가 결정적 렌더러로 내려갔다.

### 2. 스트림 오류를 삼키던 문제

과부하나 사용량 한도는 200 OK 스트림 **안에** `error` 이벤트로 온다. 그것을 건너뛰니 "모델 응답이 비어 있습니다"만 남아 원인을 알 수 없었다. `stop_reason: "max_tokens"`도 마찬가지로 감지해 `"Expected ',' or ']'"` 같은 엉뚱한 파싱 오류로 둘러대지 않는다. 원인이 다르면 고칠 곳도 다르다.

### 3. 스트리밍 중 완성된 카드 회수

응답 끝이 깨졌다고 결정적 렌더러로 내려가면, 이미 스키마 검증까지 통과해 **화면에 그려진** 카드를 지우고 훨씬 빈약한 화면으로 되돌아간다. `salvage()`는 스트리밍 중 닫힌 카드만 살린다. 새로 만드는 내용은 없고, 무엇이 깨졌는지는 `degraded`에 그대로 남긴다.

## 결과

같은 질문(`경북에서 스마트팜 창업을 준비중인 34세인데...`)의 종단 실행:

| | 이전 | 이후 |
| --- | --- | --- |
| 도구 호출 | 0건 | 3건 (`search_policies` → `search_documents` → `search_press_releases`) |
| 답변 | 실패 | 성공 |
| 카드 | 0장 | 7장 (headline · briefing · table×3 · bullets×2) |
| 출처 | 0건 | 5건 |
| 저하 | — | 없음 |

`봉화군 인구는 어떻게 변했나?`도 확인했다. 호출 2건, 카드 5장, 출처 10건. 모델이 스스로 **측정 기준이 다른 구간을 이어 붙이지 말라**는 도구의 경고를 답에 옮겼다.

## 설정

`prototype/.env.local`:

```
MCP_SERVER_URL=https://use.me.kr/mcp   # 도구 호출이 붙는 곳
MCP_BASE_URL=http://127.0.0.1:8790     # 추천 질문 목록만 여기서 가져온다
PLANNER_MODEL=gpt-5.6-sol              # 도구를 고르고 MCP를 호출
PROTOTYPE_MODEL=claude-sonnet-5        # 근거를 카드로 구성
```

두 모델의 역할 분리는 그대로다. 바뀐 것은 앞쪽 모델이 **글이 아니라 프로토콜로** 도구를 만난다는 점뿐이다.

## 남은 것

- `services/mcp-server`의 `/api/agent`와 프롬프트 플래너는 그대로 두었다. 벤치마크(`evals/`)가 그 경로를 쓰고, MCP 클라이언트가 없는 소비자를 위한 경로이기도 하다. 다만 프로토타입은 더 이상 쓰지 않으므로 `prototype/src/lib/agent.ts`의 `askAgent`는 제거했다 — 두 경로가 남아 조용히 어긋나는 것이 가장 나쁘다
- 모델이 회차마다 다른 도구를 고른다(어떤 회차는 `search_press_releases`, 어떤 회차는 `search_documents`). 시연 안정성에는 영향이 있지만, 결과 품질은 모든 회차에서 이전보다 나았다
- 추론 요약이 나오지 않는 회차가 있다. 단계 표시는 그대로 나가므로 화면이 비지는 않는다
