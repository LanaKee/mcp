# 실수: 중첩 태그를 무시한 HTML 파서

## 무엇이 잘못됐나

경상북도의회 크롤러의 첫 실행에서 두 가지 파싱 결함이 동시에 드러났다. 둘 다
**예외를 던지지 않고 조용히 빈 결과를 반환**했다는 점이 공통점이다.

### 1. 의원 명부에서 0명이 나왔다

의원 카드를 이렇게 잘라냈다.

```ts
/<div class="profile[^"]*">([\s\S]*?)<\/div>\s*<\/div>/g
```

비탐욕 매칭이라 `</div></div>`가 처음 나오는 지점에서 멈춘다. 그런데 카드
안에는 `div.name`, `div.sns`, `div.btns`가 중첩돼 있어 첫 `</div></div>`는
카드의 끝이 아니라 내부 블록의 끝이었다. 결과적으로 이름조차 포함되지 않은
조각이 잡혔고, 후속 필드 추출이 전부 실패해 **64명이 0명**이 됐다.

**수정**: 정규식으로 닫는 태그를 찾지 않고, `<div class="profile">` 여는 태그의
등장 위치들로 문서를 슬라이스하는 `profileCards()` 헬퍼로 교체했다. 다음 카드가
시작되는 곳이 이전 카드의 끝이다.

### 2. 소관위원회가 전부 null이었다

의안 상세의 표를 읽는 `tableRows()`가 `<tbody>` 안의 `<tr>`만 찾았다. 경상북도
의회의 위원회 심사 테이블 일부는 `<tbody>` 없이 `<table><tr>`로 바로 시작한다.
이 경우 "행이 없음"으로 처리되어 `committee`, `outcome`, `decidedDate`가
모두 null이 됐다.

**수정**: `<tbody>`가 있으면 그 안을, 없으면 테이블 전체에서 `<td>`를 포함한
`<tr>`을 찾도록 폴백을 추가했다.

## 왜 위험했나

두 결함 모두 **성공적으로 완료된 크롤로 보였다**. 크롤러는 종료 코드 0으로
끝났고, CSV도 정상 생성됐다. 그대로 커밋했다면 다음이 벌어졌다.

- 의원 테이블이 비어 있으므로 모든 발의자 링크의 `council_member_id`가 null이
  되고, `search_member_bills`는 어떤 의원으로 검색해도 빈 결과를 낸다.
- 소관위원회가 null이면 위원회 필터가 항상 0건을 반환한다. 사용자는 "그런 의안이
  없다"고 결론 내린다. 실제로는 데이터가 있는데 파서가 못 읽은 것이다.

즉 **잘못된 답이 아니라 "없다"는 답**이 나온다. 이쪽이 더 나쁘다. 틀린 숫자는
검증되지만 빈 결과는 사실로 받아들여지기 때문이다.

## 어떻게 잡았나

전체 크롤을 돌리기 전에 실제 페이지 3종(명부, 목록, 상세)을 fixture로 받아
파서만 단독 실행하는 probe를 먼저 돌렸다. 명부 0명과 committee null이 즉시
드러났다. 25분짜리 크롤을 돌린 뒤였다면 결과 CSV를 눈으로 훑고 "다 있네"
하고 넘어갔을 가능성이 높다.

## 규칙

1. **HTML 파서는 닫는 태그를 정규식으로 찾지 않는다.** 중첩 가능한 컨테이너는
   여는 태그 위치로 슬라이스한다.
2. **파서가 빈 결과를 반환하면 정상이 아니라 의심 대상이다.** 0건은 예외만큼
   시끄럽게 다뤄야 한다.
3. **전체 크롤 전에 fixture probe를 돌린다.** 크롤 비용이 클수록 파서 검증을
   먼저 한다.
4. 위 파싱 규칙은 `pipelines/src/gb-council.test.ts`의 11개 테스트로 고정했다.
   실제 응답에서 잘라낸 fixture를 쓰므로 사이트 마크업이 바뀌면 테스트가 깨진다.
