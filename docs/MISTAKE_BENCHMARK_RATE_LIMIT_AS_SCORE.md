# 실수 기록: 호출 실패를 모델 성능으로 측정할 뻔한 건

## 무슨 일이 있었나

`gemini-3.6-flash`로 벤치마크를 돌린 첫 결과는 다음과 같았습니다.

```
정확도    vanilla  9.1%  |  MCP 18.2%
환각률    vanilla  4.5%  |  MCP  0.0%
```

MCP arm 정확도 18.2%는 다른 모델(72~82%)에 비해 터무니없이 낮았습니다. 그대로
"gemini는 이 과제에서 약하다"고 리포트에 실었다면 완전한 오보가 되었을 것입니다.

원시 응답을 열어 보니 실제 내용은 이랬습니다.

```
===== err: Gemini 요청이 실패했습니다: 429 Too Many Requests
(empty)
```

**44건의 호출 중 36건이 모델에 도달조차 하지 못했습니다.** 측정된 것은 모델의
능력이 아니라 무료 등급 일일 할당량(모델당 20건)이었습니다.

## 왜 놓칠 뻔했나

1. **실패가 성공처럼 채점되었습니다.** 빈 응답은 "값을 단언하지 않음"이므로
   환각으로 잡히지 않고, 오히려 **환각률 0.0%라는 좋아 보이는 숫자**를 만들어
   냈습니다. 지표가 정상 범위 안에 있었기 때문에 경보가 울리지 않았습니다.
2. **집계가 오류를 흡수했습니다.** 요약 표에는 정확도·환각률·출처검증만 있었고,
   실행 자체가 성립했는지를 말해 주는 값이 없었습니다.
3. **하니스가 끝까지 완주했습니다.** 25분 동안 실패를 반복하면서도 멈추지 않고,
   마지막에 그럴듯한 형태의 리포트를 써 냈습니다.

## 교훈

**낮은 점수를 보면 모델을 의심하기 전에 측정 장치를 의심해야 합니다.**
특히 "이상하게 좋은 지표"(환각률 0%)와 "이상하게 나쁜 지표"(정확도 18%)가 같이
나타나면 거의 항상 측정이 깨진 것입니다.

집계 지표만으로는 실행의 유효성을 알 수 없습니다. 유효성은 별도로, 명시적으로
측정해야 합니다.

## 조치

1. **실행 유효성 지표 도입.** `errorRateOf()`가 호출 실패율을 계산하고, 10%를
   넘으면 `valid: false`가 됩니다. 무효 실행은 `COMPARISON.md`의 점수표에서
   제외되고 실행 조건표에만 남습니다. 삭제하지 않는 이유는 시도한 사실이 기록될
   필요가 있기 때문입니다.
2. **개별 리포트 상단 경고.** `report.md` 첫머리에 무효 표시를 넣었습니다. 표부터
   보는 독자가 경고 없이 점수를 마주치지 않도록 제목 바로 아래에 둡니다.
3. **조기 중단.** 6회 연속 호출 실패 시 리포트를 남기지 않고 중단합니다. 실제로
   `gemini-3.5-flash` 재시도에서 11번째 문항에 멈춰, 25분 대신 1분 만에 상황을
   알려 주었습니다.
4. **전송 실패 재시도.** rate limit과 5xx는 지수 백오프로 재시도합니다. 다만
   일일 한도는 이것으로 해결되지 않으며, 3번 조치가 그 경우를 담당합니다.
5. **`caseId` 기록.** `report.json`의 응답에 `caseId`가 없어 어떤 문항의 답인지
   대조할 수 없었습니다. 이번 조사도 순서에 의존해야 했습니다. 감사를 위해 저장하는
   기록이 감사에 쓸 수 없는 상태였던 셈입니다.

## 함께 발견해 고친 것

- **`compare:offline` 스크립트가 라이브 실행이었습니다.** 존재하지 않는 `--offline`
  플래그를 넘기고 있었고, 파서가 이를 조용히 무시해 오프라인이라는 이름으로 실제
  API를 호출했습니다. `--dry-run`으로 정정했습니다.
- **모듈 import만으로 `main()`이 실행되었습니다.** 진입점 판별이
  `import.meta.url.endsWith("run.ts")`였는데, 이는 테스트가 모듈을 import할 때도
  참입니다. `process.argv[1]`의 실제 경로와 비교하도록 고쳤습니다. 그대로 두었다면
  `run.ts`를 import하는 테스트가 실제 벤치마크를 API 호출까지 포함해 실행시켰을
  것입니다.
- **리포트의 서술이 데이터와 어긋났습니다.** "지연은 모든 모델에서 MCP가 더 길다"고
  하드코딩했으나 `gpt-5.6-luna`는 vanilla 7,143ms > MCP 3,951ms였습니다. 서술을
  실행 데이터에서 도출하도록 바꿨습니다.
