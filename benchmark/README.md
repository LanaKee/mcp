# Vanilla vs MCP 벤치마크 — 경상북도 컨텍스트

일반 LLM(vanilla)과 경상북도 데이터 계층에 연결된 LLM(MCP)이 **같은 질문에 대해 무엇을 다르게 답하는지** 측정한다.

이 벤치마크가 답하려는 질문은 하나다. **"그냥 ChatGPT에 물어보면 되는 것 아닌가?"**

---

## 1. 왜 별도의 벤치마크가 필요한가

기존 `evals/`는 플래너가 카탈로그 정의대로 도구를 고르는지 검증한다. 전 항목 100% 통과이며, 그럴 수밖에 없다. **자기 카탈로그를 기준으로 자기 플래너를 채점**하기 때문이다. 내부 정합성은 증명하지만 "이 시스템이 없을 때와 비교해 무엇이 나아지는가"는 전혀 증명하지 못한다.

이 벤치마크는 그 빈칸을 채운다. 비교 대상은 **동일 모델**이고, 유일한 변수는 **데이터 계층 접근 여부**다.

## 2. 설계 원칙

| 원칙 | 구현 |
| --- | --- |
| 동일 조건 | 두 arm이 같은 모델(`chatClientFromEnv()`), 같은 지시문(`SHARED_INSTRUCTION`), 같은 질문을 같은 순서로 받는다 |
| 객관적 정답 | 정답을 하드코딩하지 않고 **실행 시점에 PostgreSQL에서 조회**한다 |
| 결정론적 채점 | LLM 심판을 쓰지 않는다. 수치 비교·부재 판정·출처 조회 모두 코드로 판정한다 |
| 자기 검증 | 문항의 전제(예: "이 자료는 없다")가 현재 DB와 어긋나면 **실행을 중단**한다 |
| 불리한 문항 포함 | vanilla가 이길 수 있는 대조군을 일부러 넣는다 |

마지막 항목이 중요하다. MCP가 전승하도록 문항을 고르면 그것은 측정이 아니라 홍보다. `common_knowledge` 범주는 일반 모델도 아는 광역 통계로 구성했고, 실제로 vanilla가 득점한다.

### 왜 LLM 심판을 쓰지 않는가

자기 시스템을 자기가 만든 심판으로 평가하면 결과의 설득력이 사라진다. 이 벤치마크의 모든 판정은 다음 세 가지 결정론적 연산으로 환원된다.

1. 답변에서 수치를 추출해 DB 정답과 허용 오차 내 비교
2. 답변이 단정했는지 보류했는지 판별
3. 답변이 제시한 출처 식별자를 `data_source` 테이블에 실제로 조회

## 3. 문항 구성 (22문항 / 6범주)

| 범주 | 문항 | 측정 대상 |
| --- | ---: | --- |
| `common_knowledge` | 3 | **대조군.** 일반 모델도 아는 광역 통계. 접지(grounding)가 기존 능력을 훼손하지 않는지 |
| `recency` | 4 | 학습 컷오프 이후(2026년) 자료. 사전지식으로 도달 불가 |
| `hyperlocal` | 4 | 울릉·영양·봉화·영덕 등 소규모 군 단위 |
| `precision` | 6 | 원 단위 지방세 결산액, 보도자료 총건수 등 근사치로는 통과 불가 |
| `abstention` | 3 | **자료가 실제로 없는 질문.** 답하지 않는 것이 정답 |
| `provenance` | 2 | 수치와 함께 검증 가능한 출처 식별자를 요구 |

`abstention` 범주가 이 벤치마크의 핵심이다. 세 문항 모두 전제를 DB로 확인했다.

- `ab-uljin-pop-2015` — 울진군 인구는 2025년부터만 적재돼 있다
- `ab-cheongsong-pop-2024` — 2024년 인구 관측은 일부 지역만 있고 청송군은 없다
- `ab-policy-programs` — `policy_program` 테이블은 0행이다

전제가 깨지면(예: 나중에 울진군 2015년 자료를 적재하면) 실행이 실패하고 문항 갱신을 요구한다.

## 4. 지표

| 지표 | 정의 | 주의 |
| --- | --- | --- |
| 정확도 | 허용 오차 내 정답 비율. 부재 문항은 보류가 정답 | |
| 답변 시도율 | 보류하지 않고 단정한 비율 | |
| 환각률 (전체) | 전체 문항 중 사실과 다른 단정을 한 비율 | **단독 해석 금지** |
| 환각률 (답변 대비) | 단정한 답변 중 사실과 다른 비율 | 두 arm을 같은 조건에 놓는 값 |
| 부재 인지 정확도 | 자료 없는 문항을 올바로 보류한 비율 | |
| **출처 검증 가능 비율** | 제시한 출처 중 `data_source`에 실제로 조회되는 비율 | 아래 참조 |
| 응답 지연 중앙값 | | 접지의 비용 |

**환각률은 반드시 답변 시도율과 함께 읽어야 한다.** 모든 질문에 "모르겠습니다"라고 답하는 시스템은 환각률 0%를 기록하지만 아무 쓸모가 없다. 이 벤치마크가 두 지표를 나란히 싣는 이유다.

**출처 검증 가능 비율**은 "귀속(attribution)"과 "출처(provenance)"를 가른다. "행정안전부 주민등록 인구통계에 따르면"은 기관 이름을 댄 것이지 확인할 수 있는 지점을 가리킨 것이 아니다. MCP arm이 제시하는 `source_id`는 `data_source` 행으로 조회되고, 그 행은 파일 경로와 SHA-256까지 갖고 있다. 이 지표는 그 차이를 숫자로 만든다.

## 5. 실행

```bash
# 정답 해석과 문항 전제만 검증 (API 호출 없음)
pnpm benchmark:compare:dry-run

# 전체 비교 실행 (키 우선순위에 따라 모델 자동 선택)
pnpm benchmark:compare

# 모델을 지정해서 실행
pnpm --filter @gb/benchmark compare -- --model claude-sonnet-5

# 끝난 실행들을 모아 모델 간 비교표 생성
pnpm benchmark:compare:models

# 일부만
pnpm --filter @gb/benchmark compare -- --limit 5
```

필요 환경변수: `DATABASE_URL`, 그리고 사용할 모델의 키(`OPENAI_API_KEY` / `GROK_API_KEY` / `GEMINI_API_KEY` / `CLAUDE_API_KEY`). 공급자는 모델 id에서 추론한다.

산출물은 `benchmark/reports/<모델명>/`에 `report.md`(사람용)와 `report.json`(원시 응답·정답·판정 전체 포함)으로 떨어지고, 모델 간 비교는 `benchmark/reports/COMPARISON.md`에 모인다.

| 옵션 | 설명 |
| --- | --- |
| `--model <id>` | 모델 지정. `gpt-*`, `claude-*`, `gemini-*`, `grok-*` |
| `--dry-run` | 정답 해석과 전제 검증까지만 수행 |
| `--limit N` | 앞에서 N문항만 |
| `--cases <경로>` | 다른 문항 파일 사용 |
| `--out <경로>` | 리포트 출력 위치 |
| `--planner heuristic` | MCP arm의 플래너를 결정론적 플래너로 고정 |

호출이 6회 연속 실패하면 실행을 중단하고 리포트를 남기지 않는다. 모델 성능이 아니라 호출 실패율을 측정한 리포트가 점수처럼 보이는 일을 막기 위해서다.

## 6. 결과 (22문항, 4개 모델)

전체 표는 [`reports/COMPARISON.md`](reports/COMPARISON.md)에 있다.

| 모델 | vanilla 정확도 | MCP 정확도 | 변화 |
| --- | ---: | ---: | ---: |
| `gpt-4o-mini` | 27.3% | **72.7%** | +45.5p |
| `gpt-5.6-luna` | 36.4% | **81.8%** | +45.5p |
| `claude-sonnet-5` | 50.0% | **81.8%** | +31.8p |
| `gemini-3.6-flash` | — | — | 측정 불가 |

유효한 실행 3개 모두에서 MCP arm이 더 정확했다. `gemini-3.6-flash`는 무료 등급
할당량이 **모델당 하루 20건**인데 1회 실행에 44건이 필요해 측정할 수 없었다(실패한
실행은 무효 표시와 함께 `reports/gemini-3.6-flash/`에 남겨 두었다).

**모델 간 절대 점수 비교는 이 벤치마크의 목적이 아니다.** 22문항은 순위를 매기기에
너무 적고, `gpt-5.6-luna`와 `claude-sonnet-5`는 `temperature`를 아예 거부해
재현성이 낮다. 읽어야 할 값은 각 모델 *내부*의 vanilla → MCP 변화량이다.

### gpt-4o-mini 상세 (22문항)

| 지표 | vanilla | MCP |
| --- | ---: | ---: |
| 정확도 | 27.3% | **72.7%** |
| 답변 시도율 | 27.3% | 81.8% |
| 환각률 (전체) | 9.1% | 18.2% |
| 환각률 (답변 대비) | 33.3% | **22.2%** |
| 부재 인지 정확도 | 66.7% | 66.7% |
| 출처 검증 가능 비율 | 0.0% | **56.8%** |
| 응답 지연 중앙값 | 723ms | 2,429ms |

범주별로 보면 성격이 분명해진다(`gpt-4o-mini` | `gpt-5.6-luna`).

| 범주 | vanilla (4o-mini \| luna) | MCP (4o-mini \| luna) |
| --- | ---: | ---: |
| 일반 상식 (대조군) | 100.0% \| 100.0% | 66.7% \| 100.0% |
| 최신성 | 0.0% \| 50.0% | 75.0% \| 75.0% |
| 지역 밀착 | 0.0% \| 50.0% | 100.0% \| 100.0% |
| 정밀도 | 0.0% \| 0.0% | 50.0% \| 50.0% |
| 부재 인지 | 66.7% \| 0.0% | 66.7% \| 100.0% |
| 출처 검증 | 50.0% \| 50.0% | 100.0% \| 100.0% |

대조군인 일반 상식에서는 vanilla가 만점이고, `gpt-4o-mini`에서는 MCP arm이 오히려
더 낮다. 이 벤치마크가 MCP에 유리하게만 짜여 있지 않다는 근거다.

### 무엇이 실제로 드러났는가

**모델이 강해지면 vanilla의 실패 양상이 침묵에서 단언으로 바뀐다.**

| 모델 | vanilla 답변 시도율 | vanilla 환각률(답변 대비) |
| --- | ---: | ---: |
| `gpt-4o-mini` | 27.3% | 33.3% |
| `gpt-5.6-luna` | 100.0% | 63.6% |
| `claude-sonnet-5` | 100.0% | 50.0% |

`gpt-4o-mini`만 측정했을 때의 결론은 "vanilla의 지배적 실패는 환각이 아니라
침묵"이었다. 이는 모델 일반의 성질이 아니라 그 모델의 성질이었다. 지시문 탓도
아니다 — 지시문을 완전히 제거한 맨 프롬프트로도 동일하게 거부한다.

```
$ (지시문 없이) "2024년 경상북도 구미시의 주민등록 인구는 몇 명입니까?"
→ "2024년 경상북도 구미시의 주민등록 인구에 대한 정확한 수치는 제공할 수 없습니다.
   최신 통계는 구미시청이나 통계청의 공식 자료를 참고하시기 바랍니다."
```

반면 `gpt-5.6-luna`는 22문항 전부에 답하고, **그중 63.6%가 사실과 달랐다.**
`claude-sonnet-5`도 전부 답하고 절반이 틀렸다.

따라서 이 데이터 계층의 가치는 두 가지로 서술된다. 약한 모델에는
**"답할 수 없던 질문을 답할 수 있게 만든다"**, 강한 모델에는
**"자신 있게 지어내던 답을 검증 가능한 출처가 있는 답으로 바꾼다"**. 모델이 커질수록
근거 계층이 덜 필요해지는 것이 아니라, 실패가 눈에 덜 띄는 형태로 바뀌므로 더
필요해진다. vanilla의 출처 검증 가능 비율은 세 모델 모두 **0.0%**다. 출처를 대지
않아서가 아니라, 대는 출처가 실재하지 않기 때문이다.

## 7. 이 벤치마크가 찾아낸 우리 시스템의 결함

MCP arm이 틀린 문항은 모두 실제 결함을 가리킨다. 벤치마크의 산출물은 점수가 아니라 이 목록이다. 특히 **아래 4건은 모델 3종 전부에서 실패했다.** 모델을 바꿔도 재현되므로 모델의 특성이 아니라 시스템의 결함으로 확정된다.

| 문항 | 실패 모델 | 증상 | 진단 |
| --- | --- | --- | --- |
| `pr-press-count-2025` | 3/3 | 총 2,770건인데 "총 5건"이라 답변 | `search_press_releases`의 top-N 결과 개수를 전체 건수로 오인. **집계 도구가 없다** |
| `pr-council-seats-ppp` | 3/3 | 정당별 의원 수를 못 셈 | 의원 명부에 대한 집계 도구 부재 |
| `rc-bill-count-2026` | 3/3 | 연도별 의안 건수를 못 셈 | 의안에 대한 집계 도구 부재 |
| `pr-gyeongsan-tax-burden-2024` | 3/3 | '신고 총 세부담액'을 물었는데 '수납액'을 반환 | `get_local_tax_revenue_trend`가 `amount_semantics`를 인자로 노출하지 않아 두 정의를 구분할 수 없다 |
| `ck-gyeongbuk-pop-2024` | 1/3 | 광역(경상북도) 인구를 물었는데 포항시 값(499,352)을 반환 | 광역 단위 지역 해석. 3종 중 1종에서만 실패하므로 도구가 아니라 플래너의 인자 선택 문제에 가깝다 |

즉 가장 큰 단일 개선 과제는 **집계(count/sum/group-by) 도구의 부재**다(3/3 실패 4건 중 3건). 그 다음이 **지표 정의(semantics) 선택 인자**이며, 광역 단위 해석은 모델에 따라 성공하므로 우선순위가 낮다.

## 8. 한계

- **실행 간 변동.** LLM은 비결정론적이라 반복 실행 시 범주별 수치가 흔들린다(특히 문항 수가 3~4개인 범주). 실제로 `gpt-4o-mini`는 동일 조건 재실행에서 정확도가 18.2% → 27.3%로 움직였다. 결론에 인용할 때는 여러 번 실행해 확인해야 한다.
- **temperature를 고정할 수 없는 모델이 있다.** `gpt-5.6-luna`와 `claude-sonnet-5`는 `temperature` 지정을 거부한다. 해당 실행은 재현성이 낮으며 리포트에 `temperaturePinned: false`로 기록된다.
- **모델 3종.** OpenAI 2종과 Anthropic 1종을 측정했다. Gemini 계열은 무료 등급 일일 한도(모델당 20건) 때문에 미측정이다.
- **모델 간 절대 점수 비교는 유효하지 않다.** 22문항으로는 모델 순위를 매길 수 없다. 유효한 것은 각 모델 내부의 arm 간 차이뿐이다.
- **표본 22문항.** 방향성을 보기엔 충분하지만 소수점 단위 비교에는 부족하다.
- **거부 판별은 어휘 기반.** 두 arm에 동일하게 적용되므로 편향은 없으나 완벽하지 않다.
- **지연 시간 비교는 불리하게 잡혀 있다.** MCP arm은 도구 실행 + 합성까지 2단계를 거치므로 느린 것이 당연하다. 접지의 비용으로 그대로 싣는다.

### 실행 유효성을 별도로 측정하는 이유

정확도·환각률만 보면 호출이 전부 실패한 실행과 모델이 답을 회피한 실행을 구분할 수
없다. 실제로 `gemini-3.6-flash`의 첫 실행은 44건 중 36건이 429로 실패했는데, 빈
응답은 아무것도 단언하지 않으므로 **환각률 0.0%라는 좋아 보이는 숫자**를 만들어
냈다. 그래서 호출 실패율을 따로 계산하고, 10%를 넘는 실행은 비교표에서 제외한다
(→ `docs/MISTAKE_BENCHMARK_RATE_LIMIT_AS_SCORE.md`).

### 한국어 수치 파서가 필요한 이유

접지된 답변은 "132,550명"이라 쓰고, 접지되지 않은 답변은 "약 13만 2천 명"이라 쓴다. 둘 다 같은 사실을 말하려는 시도다. 한쪽 표기만 이해하는 채점기는 정확도가 아니라 문체를 측정하게 된다.

### MCP arm이 2단계인 이유

실제 MCP 클라이언트는 도구 호출에서 멈추지 않는다. 조회된 행을 모델에 되돌려주고 모델이 답변을 작성한다. 1단계(도구 실행)만 평가하면 *모델*과 *데이터 덤프*를 비교하게 되어 접지의 효과를 과소평가한다. 그래서 MCP arm은 도구 실행 후 **같은 모델에 같은 지시문 + 조회 결과**를 주어 답변을 합성한다.
